# 尚未适配的项目

目的：先回答用户想做的操作现在能否参与，再读取完成它所需的协议细节。用户要求独立审计、投资研究或完整分析时按该范围展开。

## 最小发现

1. 看 project.preflight.priorResearch。旧研究只是线索，不能复用其中的供应、价格、余额、期限或执行授权。
2. 浏览器工作遵循已安装 playwright-chrome-browser skill。复用一个隔离的 Chrome / Playwright 上下文，在同一轮读取官网可见的参与方式、网络、供应 / 开关和价格。
3. 官网已提供 agent guide、API、配置时，只读其中与当前操作有关的部分。下载型 .md / JSON 用 Playwright 请求 API 取正文，避免 page.goto 触发下载后重新导航。不要猜不存在的 API 端点。
4. 已知只读查询可并发。首先查可参与性；售罄或关闭时，只核对决定结论的链上状态，然后结束。无需继续资格检查或签名 schema 研究。
5. 仍可参与时，再核对合约、ABI、身份条件、签名 schema 和费用；需要接新 schema 时明确适配缺口，不能放宽成任意签名。

不要默认整页截图、读全部前端模块、白皮书或整个外部 skill。可见文案和协议已足够时，不另开区块浏览器；403 / 下载失败只说明读取失败，不要反复换入口消耗时间。工具结果只返回决定下一步的字段，原始资料需要时写本地文件。读取过的技能规范按相关流程复用，不因同一项目的每次小查询再全文输出。
